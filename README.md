# Fragrances & Co

Многостраничный сайт поставщика промышленного сырья и парфюмерных отдушек. React 18 + Vite 7, React Router 7, Tailwind CSS 4, GSAP / ScrollTrigger / `useGSAP`, Express 5, Prisma 6 и SQLite.

## Быстрый запуск

Нужен Node.js 22.12+ (проверено на 22.17.1).

```sh
npm ci
npm run setup
npm run admin:password
npm run dev
```

Сайт: **http://localhost:5173**, админка: **http://localhost:5173/admin**, API: **http://127.0.0.1:3001/api**. Открывайте сайт с origin, указанным в `SITE_URL`: запросы с другого origin отклоняются.

`setup` создаёт `.env` из примера, генерирует Prisma Client, применяет миграции и добавляет 6 демонстрационных товаров. Повторный запуск не перезаписывает существующие товары. Команда `admin:password` интерактивно устанавливает пароль длиной от 12 символов до 72 байт UTF-8; ввод виден только в вашем терминале. В `.env` сохраняется bcrypt-хеш, старое значение `ADMIN_PASSWORD` очищается. Email администратора задаётся в `ADMIN_EMAIL` (по умолчанию `admin@fragrances.local`). После смены настроек перезапустите API. Готового общего пароля нет.

Пароль можно задать в корневом `.env` одним из двух способов:

```dotenv
ADMIN_EMAIL=admin@fragrances.local
ADMIN_PASSWORD="ваш пароль"
ADMIN_PASSWORD_HASH=
```

Либо оставьте `ADMIN_PASSWORD` пустым и используйте bcrypt-хеш в `ADMIN_PASSWORD_HASH`, полученный командой `npm run admin:password`. Если заполнены оба значения, используется хеш. Обычный пароль нельзя записывать в `ADMIN_PASSWORD_HASH`: сервер сообщит об ошибке конфигурации. Значения с `#` или пробелами заключайте в кавычки. Пароль не обрезается и не очищается от пробелов. `.env` читается при запуске из корня проекта независимо от рабочей директории; после его изменения остановите и снова запустите `npm run dev`.

## Структура

```text
images/                  логотип, favicon, иллюстрации, загруженные изображения
client/src/
  components/            шапка, подвал, SEO, карточки, формы, анимации
  context/               язык, данные каталога и публичные настройки
  locales/               ru.json, uz.json, en.json
  pages/                 страницы сайта и панель администратора
  lib/                   клиент API и загрузка данных
server/src/              Express, сессии, валидация, Telegram, обработка файлов
server/test/             интеграционные тесты с изолированной SQLite
prisma/                  схема, SQL-миграции, наполнение каталога
scripts/                 подготовка окружения и установка пароля
```

## Страницы и возможности

- `/` — главный экран с параллаксом, о компании, счётчики, отрасли, популярные товары из БД (`isFeatured`), форма заявки.
- `/about`, `/applications`, `/contacts` — компания, четыре отрасли и контакты.
- `/collection` — поиск, фильтрация по отраслям, сортировка; состояние хранится в URL.
- `/collection/:slug` — карточка продукта, галерея, профиль и переход к заявке с выбранным продуктом.
- `/request` — полная форма заявки, валидация, согласие и номер принятой заявки.
- `/privacy` — исходный текст политики обработки данных для согласования владельцем.
- `/admin` — вход, создание / изменение / удаление товаров на трёх языках, загрузка и удаление изображений, отметки «на главной» и «демонстрационный», управление категориями, журнал заявок с пагинацией и статусом Telegram.

В разделе «Категории» можно создавать категории, менять их названия на RU / UZ / EN и код (slug), удалять пустые категории. Названия автоматически используются в фильтрах каталога, карточках и форме товара. Изменение slug сохраняет все связи с товарами через внешний ключ `ON UPDATE CASCADE`. Категорию с товарами удалить нельзя: сначала перенесите товары в другую категорию. Четыре отрасли на странице «Применение» остаются редакционным содержимым сайта и не зависят от категорий каталога.

Миграция `20261019010000_categories` переносит существующие категории в отдельную таблицу, сохраняя товары, изображения и заявки; нестандартные старые категории также сохраняются. При обновлении другой установки остановите API, выполните `npx prisma generate`, `npm run db:migrate`, `npm run build` и запустите сервер снова. На Windows остановка API нужна, чтобы его процесс не блокировал DLL Prisma. Повторное наполнение каталога не воссоздаёт категории, удалённые или переименованные через админку.
- `/sitemap.xml`, `/robots.txt` — формируются Express; sitemap включает товары из базы, админка исключена.

RU / UZ / EN переключаются без перезагрузки через контекст. Язык сохраняется в localStorage и `?lang=`. Helmet задаёт title, description, canonical, alternate, Open Graph и язык документа. Это SPA с метаданными на стороне клиента: для предпросмотра отдельных товарных карточек в ботах без JavaScript понадобится SSR или пререндеринг.

Анимации очищаются через `useGSAP` и `gsap.matchMedia`; при `prefers-reduced-motion` отключены. Формы поддерживают клавиатуру, видимый фокус и сообщения об ошибках. Изображения каталога загружаются лениво.

## Telegram

В корневом `.env` укажите:

```dotenv
TELEGRAM_BOT_TOKEN=ваш_токен
TELEGRAM_CHAT_ID=идентификатор_чата
```

Создайте бота через BotFather, начните с ним диалог или добавьте его в нужную группу с правом отправки сообщений. Настройка назначения и отправка основаны на [официальном Telegram Bot API](https://core.telegram.org/bots/api#sendmessage).

Заявка **сначала сохраняется в SQLite**, затем отправляется уведомление. При отсутствии настроек, сетевой ошибке или таймауте заявка остаётся в журнале администратора. API возвращает посетителю факт сохранения, а не неподтверждённую доставку Telegram. Сервер раз в минуту повторяет неудачные отправки, максимум 5 попыток на заявку. Можно запустить `npm run telegram:retry` или повторить отправку из админки. После 5 попыток требуется диагностика и ручное исправление записи владельцем БД. При неоднозначном сетевом таймауте Telegram может получить дубликат; номер заявки в уведомлении позволяет его распознать.

Токен не попадает в клиентскую сборку, URL сайта или серверные логи. Реальная доставка требует ваших настроек; тесты используют имитацию ответа Telegram.

## Изображения и содержимое

Логотип и favicon перенесены из исходной папки `img/`, оригиналы сохранены. Все новые изображения находятся в `/images`; `/hero-bg.jpg` также доступен отдельным адресом. Происхождение изображений и финальные промпты записаны в [images/ASSETS.md](images/ASSETS.md).

В админке можно загрузить до 6 изображений на товар: JPEG / PNG / WebP, до 8 МБ и 25 мегапикселей. Фактическое содержимое проверяется Sharp, изображение перекодируется в WebP, ограничивается 1600×1600 и получает случайное имя. Исходное имя и MIME не считаются доверенными. SVG и произвольные файлы не принимаются. Пути хранятся в `ProductImage`; физические файлы — в `images/uploads/`.

Демонстрационные товары и фотографии явно отмечены. Достоверные стаж компании, объёмы и география поставок, партнёры и сертификаты не предоставлены, поэтому численные показатели компании не выдуманы. Перед публикацией замените примеры реальными товарами и подтвердите тексты. В контактах настроены телефон `+998 93 385 48 88` и Telegram `@Otdushkiuz`. Значения задаются в корневом `.env`: `CONTACT_PHONE`, `CONTACT_TELEGRAM`, `CONTACT_EMAIL`, `CONTACT_ADDRESS`; пустые поля скрываются. Согласуйте юридические реквизиты, политику обработки данных и сроки хранения с владельцем бизнеса.

Публичная ссылка Telegram формируется из `CONTACT_TELEGRAM` (имя пользователя с `@` или без). Она доступна в шапке, подвале, рядом с формами, на странице контактов и в плавающей кнопке справа снизу на всех публичных страницах. На телефоне кнопка компактная и скрывается, пока фокус находится внутри формы. Подпись переведена на RU / UZ / EN. Для уведомлений о заявках используются отдельные переменные `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`. После изменения `.env` перезапустите API.

## Сборка и развёртывание

Подробная инструкция для Linux VPS с SSH, systemd, Nginx, HTTPS, обновлениями и резервным копированием: [deploy.md](deploy.md).

```sh
npm run build
npm test
npm audit --omit=dev
```

В production установите `NODE_ENV=production`, `SITE_URL=https://ваш-домен`, `ADMIN_EMAIL`, `ADMIN_PASSWORD_HASH` (или `ADMIN_PASSWORD`), `DATABASE_URL` и Telegram-настройки. Можно задать их в окружении процесса вместо `.env`. Без HTTPS `SITE_URL` и настроенного пароля администратора production-сервер не запустится.

```sh
npm ci
npm run setup
npm run build
npm start
```

Express раздаёт `client/dist`, изображения и API на одном origin. Приложение слушает `127.0.0.1:3001`; поставьте перед ним HTTPS reverse proxy с ограничением тела запроса 9 МБ и сжатием ответов. Устанавливайте `TRUST_PROXY=1` только за одним доверенным proxy, переписывающим forwarding-заголовки. SQLite-версия рассчитана на один процесс API и постоянный диск. Храните БД и `images/uploads` на постоянном томе и резервируйте их вместе. Для согласованного backup остановите запись или используйте SQLite backup API; не копируйте активный файл БД без учёта WAL.

Переход на PostgreSQL: измените provider и `DATABASE_URL`, создайте **новые PostgreSQL-миграции** и отдельно перенесите данные. Текущие SQL-миграции предназначены для SQLite и не должны применяться к PostgreSQL.

Сессии хранятся в БД 8 часов; cookie имеет HttpOnly / SameSite=Strict и Secure в production. Изменяющие запросы требуют корректный Origin, административные — также CSRF-токен. Пароль хешируется bcrypt с cost 12. Есть ограничения частоты входа и отправки заявок, серверная Zod-валидация, ограничение размера тела и security headers. Не публикуйте `.env`, БД, кеши и загруженные файлы в Git.

На Windows Vite использует native config loader и resolver для prebundle, чтобы esbuild не обращался к недоступным родительским каталогам в ограниченном окружении. На других платформах работает стандартный resolver. Prisma 6 закреплён; `deepmerge-ts` обновлён через override до исправленной версии. Lock-файл включён для воспроизводимой установки.

## Проверки

`npm test` запускает реальные операции Prisma в отдельной временной SQLite и проверяет публичное API, валидацию, Origin / CSRF, сессии, CRUD и переводы, загрузку с проверкой байтов, сохранение заявки, сбой и повторную доставку Telegram, сохранение истории при удалении продукта и выход из сессии. Рабочая база не используется. Браузерные снимки и вспомогательные QA-артефакты находятся в игнорируемой папке `output/playwright/`.
